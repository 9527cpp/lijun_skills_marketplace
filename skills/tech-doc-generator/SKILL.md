# 技术文档生成器

根据用户提供的技术方向，自动搜索网络资源并生成结构化的技术文档。

## 输入处理

用户输入可能是：
- **模糊方向**：如 "rockchip mpp 图像质量调优"
- **明确主题**：如 "Linux V4L2 框架分析"
- **性能相关**：如 "GPU 性能优化"
- **代码相关**：如 "Android Binder 驱动分析"

首先识别技术方向类型：
- **性能方向**：包含"性能"、"优化"、"benchmark"、"延迟"、"吞吐量"等关键词
- **代码方向**：包含"框架"、"驱动"、"源码"、"代码"、"实现原理"等关键词
- **通用方向**：其他技术主题

## 文档结构模板

### 1. 背景介绍

根据搜索结果，编写 2-3 段背景介绍，包括：
- 该技术的起源和发展历程
- 为什么需要这项技术/方法
- 在行业中的应用场景

### 2. 名词解析

提取 5-10 个核心名词，每个名词包含：
- **名词**：英文名称（如果有）
- **定义**：简洁的定义
- **作用**：该组件/概念在整体方案中的作用

### 3. 原理介绍

详细解释核心技术原理，包括：
- 工作机制
- 关键算法或流程
- 数据流处理方式
- 关键参数说明

### 4. 技术实现

#### 性能方向额外内容

性能方向文档需要额外包含：

**性能优化方法**
- 列出 3-5 种核心优化方法
- 每种方法包含：
  - 优化原理
  - 实现思路
  - 预期效果

**性能数据对比**
- 优化前后性能对比表格
- 包含具体数值和百分比提升
- 标注测试环境和条件

#### 代码方向额外内容

代码方向文档需要额外包含：

**核心代码解析**
- 选取 3-5 个核心函数/结构体
- 每个包含：
  - 函数签名
  - 功能说明
  - 关键代码片段（保留原始注释）

**代码调用流程**
- 用 ASCII 图或 mermaid 语法绘制调用流程图
- 标注关键路径和分支条件

**代码架构图**
- 用 mermaid 或 ASCII 绘制架构层次图
- 标注各层职责和交互方式

### 5. 核心流程

用流程图或步骤列表展示：
- 主要操作流程
- 关键决策点
- 异常处理流程

### 6. 注意事项

整理 5-8 条实践中的注意事项：
- 常见错误和避坑指南
- 配置建议
- 兼容性注意事项
- 安全性考虑

## 搜索策略

### 步骤 1：确定搜索关键词

根据用户输入提取核心关键词，并组合多种搜索变体：

```bash
# 示例搜索策略（rockchip mpp 图像质量调优）
# 1. 官方文档
# 2. 技术博客
# 3. 社区讨论
```

### 步骤 2：执行搜索

使用 exa-web-search MCP（如果有）或 WebSearch 工具搜索：

1. **官方文档/权威来源优先**
   - 官方网站
   - 官方文档
   - GitHub README

2. **技术博客/教程**
   - 掘金、知乎、CSDN
   - Medium、dev.to
   - 个人技术博客

3. **社区讨论**
   - Stack Overflow
   - Reddit
   - 各技术论坛

### 步骤 3：内容提取

对每个搜索结果：
1. 获取完整页面内容
2. 提取关键技术点
3. 记录来源链接
4. 标记内容质量（高/中/低）

## 输出目标

生成完成后：
1. 询问用户是否需要保存到文件
2. 如果需要，保存为 `{主题}_技术文档.md`
3. 询问是否需要发布到企业微信文档（如果企业微信 MCP 可用）
